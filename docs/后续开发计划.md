# 企业级数字孪生低代码平台 — 后续开发计划

> 基于《需求拆解与业务模块梳理》《详细设计文档》与当前代码现状（Phase 1 已完成）制定。
> 更新日期：2026-09-10

## 一、现状盘点（代码 vs 文档）

### 已完成（Phase 1，质量可用）
- **工程底座**：pnpm Monorepo（shared-types / rendering-engine / widgets / frontend / backend）、ESLint+Prettier+Husky+commitlint、Docker 编排。
- **后端**：认证（JWT 双 Token + 无感刷新）、RBAC（用户/角色/权限/操作日志）、场景 CRUD（发布/克隆/版本/回滚）、组件管理、文件上传（分片+秒传+断点续传）、数据源管理（连通性测试+查询代理）、IoT 设备/属性/遥测、统一响应契约与错误码分段、Swagger。
- **前端编辑器**：三栏编排（组件库/画布/大纲）、属性/数据/事件/样式面板、Transform 编辑、撤销重做、运行时预览（data-runtime / event-runtime）。
- **渲染引擎**：TwinViewer 双引擎融合（坐标转换、相机同步、LOD、拾取、漫游、性能监控、资源释放）。
- **组件库**：图表 4 类 + UI 7 类 + WidgetRenderer + 注册表。

### 主要缺口（对照文档逐项确认）
| 文档要求 | 现状 | 缺口 |
| --- | --- | --- |

| WebSocket 实时推送 | 依赖已装（socket.io），无 Gateway | 无 ws 通道，预览页实时数据靠轮询 |
| 告警规则引擎 | `iot_alert_rule`/`iot_alert_event` 表已建 | 无规则评估服务、无接口、无前端页面 |
| 协同编辑（Yjs） | 无 | 无 |
| 场景发布后访问（大屏运行时 + 访问鉴权） | 仅编辑器内预览 | 无发布态渲染路由、无发布 token |
| 模板市场 | 无 template 模块 | 设计文档有 `biz_template` 表定义 |
| 自定义组件沙箱 | 有 ScriptEditorDialog | 无安全执行沙箱 |
| 测试 / CI-CD | 无用例、无流水线 | 文档要求单测 >80%、Playwright E2E、GitFlow |

## 二、开发计划（四个迭代，约 10~12 周）

### Sprint 1：数据实时化链路（最高优先级，约 3 周）
目标：数据从"静态配置"变成"活的"，这是数字孪生平台的灵魂，也是后续告警、联动的地基。

1. **WebSocket Gateway**（后端 + 前端）
   - 新增 `modules/gateway`：Socket.IO 网关，JWT 握手鉴权，按 `sceneId` 房间订阅。
   - 事件：`device:telemetry`、`device:status`、`alert:triggered`、`scene:data-update`。
   - 前端 data-runtime 增加 WS 适配器，替代轮询；断线自动重连 + 房间重订阅。
2. **MQTT 接入**（真实协议，先做最常用的一种）
   - 后端用 `mqtt.js` 建立订阅客户端（每个 MQTT 数据源一个连接，生命周期管理 + 重连）。
   - 遥测 topic 消息 → 解析 → 写 `iot_device_telemetry` → 广播 Gateway 房间。
   - OPC-UA（`node-opcua` 订阅模式）与 Modbus（轮询模式）排在其后，抽象出统一的 `ProtocolDriver` 接口（connect/read/subscribe/parse），三种协议实现同一契约。
3. **模拟数据源 + 演示脚本**
   - docker-compose 增加一个 EMQX/Mosquitto + 模拟设备发布脚本，让"设备发热变红、风扇转动"链路可以端到端演示。
4. **遥测查询优化**
   - 遥测表按时间分区 + 聚合查询接口（1m/1h 降采样），为图表组件提供 history API。

验收：编辑器绑定 IoT 数据源的组件在预览页实时跳动；MQTT 断连自动恢复；100 msg/s 下前端 FPS 稳定。

### Sprint 2：告警规则引擎 + 仿真应用层（约 3 周）
目标：完成需求文档"模块四：仿真分析与业务应用"的核心价值输出。

1. **规则引擎**（后端新模块 `modules/alert`）
   - 规则 CRUD 接口（表已有，补 controller/service + 错误码）。
   - 内存规则评估器：遥测流入时匹配规则（阈值/条件表达式 JSONB），去抖窗口（持续 N 秒触发才告警）。
   - 触发 → 写 `iot_alert_event` → WS 推送 `alert:triggered` → 预览页三维模型闪烁/高亮（联动 WidgetRenderer + rendering-engine 的 effects）。
   - 通知渠道先做站内 + Webhook，邮件/短信留接口。
2. **告警前端**：设备页新增规则管理；预览页告警列表抽屉 + 三维联动；告警事件确认/处理流程。
3. **空间分析第一批**（rendering-engine）
   - 距离/面积测量、通视分析；轨迹回放（结合已有 roam）。

验收：设定温度阈值告警 → 三维设备变红 + 告警抽屉出现事件 → Webhook 收到通知。

### Sprint 3：发布运行时 + 场景轻量化编辑（约 3 周）
目标：打通"编辑 → 发布 → 访问"闭环，这是低代码平台的交付形态。

1. **大屏发布运行时**
   - 发布时生成场景快照（已有 biz_scene_version）+ 发布访问令牌（签名 URL / 短 token）。
   - 新增 `/screen/:id` 公开路由：只读运行时（复用 PreviewView + data-runtime + event-runtime），不含编辑器代码（动态 import 拆包，避免编辑器被打进发布包）。
   - 发布页支持访问密码与有效期，Nginx 配置 `/ws` 代理（详细设计文档 6.4）。
2. **3D 场景轻量化编辑器**
   - 模型节点树面板（Three.js scene graph 遍历 + 选择/隐藏/隔离）。
   - 材质替换（上传贴图 → 替换 map；颜色/金属度/粗糙度编辑）。
   - 动画配置（GLTF clip 播放控制、绑定数据驱动动画如"风扇转速=温度"）。
3. **模板体系**
   - `biz_template` 表 + 模块；"当前场景另存为模板" / "从模板创建场景"；预置 2~3 个行业模板（智慧园区/工厂）作为种子数据。

验收：发布的场景用无痕浏览器+发布链接可访问，实时数据与告警联动正常；从模板 3 分钟建出一个可演示场景。

### Sprint 4：质量、安全与运维（约 3 周，可与 Sprint 3 部分并行）
1. **测试补齐**
   - 后端：Jest 单测（auth/scene/data/alert service）+ Supertest 集成测试，核心模块覆盖率 > 80%。
   - 前端：Vitest 覆盖 widgets 与 rendering-engine 纯逻辑（coordinate/camera-sync/perf）。
   - E2E：Playwright 覆盖"登录 → 建场景 → 拖组件 → 保存 → 发布 → 预览"主链路。
   - CI：GitHub Actions（或公司 GitLab CI）：lint → typecheck → test → build → Docker 镜像。
2. **多租户落地**
   - BaseEntity 统一注入 tenant_id；请求上下文（AsyncLocalStorage）自动过滤；越权访问用例进入测试。
3. **自定义组件沙箱**（如排期允许，可推到 Phase 3 后半）
   - Web Worker + 代理对象的脚本执行沙箱，禁止 DOM/网络直访；组件 config_schema 校验。
4. **运维可观测**
   - Winston 结构化日志（traceId 贯穿）+ `/metrics`（Prometheus 格式）；前端 perf monitor 上报 FPS/内存（已有 monitor 包，补上报通道）。

## 三、依赖与风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| OPC-UA/Modbus 在 Windows 开发环境难验证 | 需要真实 PLC 或模拟器 | 优先 MQTT + 模拟器；OPC-UA 用 node-opcua 自带的模拟 Server |
| 协同编辑（Yjs）复杂度高 | 与现有"保存 JSON 快照"模型冲突大 | 推迟到 Phase 3 后半，先保证单人编辑体验与发布闭环；期间用"乐观锁 + 版本对比"防覆盖 |
| WS 推送与轮询双轨维护成本 | data-runtime 已有轮询实现 | WS 适配器实现同一 DataSource 接口，轮询作为降级 |
| TimescaleDB 引入增加部署复杂度 | docker 需换镜像 | 先用分区表 + 聚合查询过渡，量级上来再切换 |

## 四、里程碑建议（对应需求文档"建议推进方向"）

- **M1（Sprint 1 末）**：数据底座可演示 —— MQTT 设备数据实时驱动大屏。
- **M2（Sprint 2 末）**：业务价值可演示 —— 告警联动三维 + 空间分析。
- **M3（Sprint 3 末）**：交付闭环可演示 —— 编辑/发布/大屏访问/模板。
- **M4（Sprint 4 末）**：企业级达标 —— 测试覆盖率、CI/CD、多租户、可观测。

Phase 3 中推迟项（Yjs 协同、组件沙箱、多租户计费）在 M4 后按业务优先级排期。
